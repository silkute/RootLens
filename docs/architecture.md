# Architecture

The hub is one Go process serving REST and embedded Vue assets. It owns SQLite,
authentication, rule evaluation, retention and report export. Agents initiate TLS
connections and never expose a listening control port. The browser polls only while
visible. There is no broker, cloud dependency, general plugin runtime or remote shell.

## Decisions

1. **Separate agent and hub:** host mounts and Docker access never enter the hub.
2. **SQLite WAL:** one serialized writer, short bounded reads, FULL synchronization,
   local-filesystem storage. Agent acknowledgement follows transaction commit.
3. **Entity samples:** one JSON metric payload per entity and interval, instead of a
   row for every scalar. Metadata is relational and only versioned when it changes.
4. **Deterministic rules:** pure Go evaluation shared by ingestion and metric replay.
   Incident updates and serialized rule state commit with their triggering frames.
5. **Capability limits:** unsupported, denied and failed collectors are separate from
   zero-valued measurements. Raw counter baselines are invalidated on resets or gaps.
6. **Bounded history:** raw 48h, minute 14d, quarter-hour 180d by default. Rollups track
   covered duration, weighted gauge sums and counter totals. Request time is derived
   from operation totals rather than averaging averages.
7. **Original Vue UI:** Reka supplies accessible interactions; RootLens owns layout
   and styling; uPlot is wrapped once. All fonts and scripts are local.

## Implemented contract choices

The authoritative transport definitions are Go types. `go run ./cmd/contracts`
generates OpenAPI, TypeScript and metric documentation from those types. This reverses
the proposed OpenAPI-first generation direction, keeping the Go binary's contract
and the browser model synchronized with fewer build dependencies.

Container network stats use the configured frame cadence rather than a separate
ten-second interval. This keeps delta totals and denominators consistent. Requests
use four workers and a shared two-second deadline. This overhead must be benchmarked
with the complete Docker daemon/proxy path, not only the agent process.

The optional current-process endpoint receives opt-in snapshots every fifteen seconds.
Only names, PIDs, resident memory and observed CPU rates are included. The hub keeps
the latest snapshot in memory; it never writes process lists into metric history.
Manual investigations currently replay up to six hours of retained native-resolution
metrics. Older incidents retain independent report evidence.

## Identity and lifecycle

Host IDs are generated by the hub. Agent tokens are hashed in SQLite and bound to a
single host. Sequence/payload conflicts are rejected. Host source intervals must
advance, and counter generations change on boot/container restart. Docker container
IDs are complete IDs, not names. A recreated container has distinct history.

The agent's in-memory retry buffer is limited to ten minutes and 32 MiB. Losing data
is reported. Hub state is persisted; agent restarts intentionally do not preserve
unsent buffers. Version 1 protocol additions must be backward-compatible.

## Security boundaries

The local administrator can view host/container information and change retention or
agent enrollment. Agent credentials can submit telemetry only. The hub cannot change
agent permissions, execute actions on a host, or operate Docker containers.

No network filesystem is supported for the SQLite directory. CPU and memory targets
are qualification goals, not guarantees. See validation documentation for remaining
hardware, soak, storage-pressure and migration qualification work.
